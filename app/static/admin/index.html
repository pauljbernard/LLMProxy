Routing Strategy

              

                

                  
                  
                  
Controls how the router ranks entries that already match a request equally on domain/task/tag/region specificity. balanced (default) blends quality, cost, and latency into one score; latency/cost/quality instead rank by that single factor first, falling through to the others — then recency — only to break remaining ties.

The package to act on, by its alias. Activate requires that package's promotion status to be approved; Rollback instead requires this alias to currently appear in the active routing policy — each button checks a different precondition, and the fields below apply only to Activate.

                  

                  

                    
                    
                    
How Activate registers this deployment in the routing policy — production takes live traffic immediately, canary takes the percentage set below, shadow never takes live traffic and exists only for side-by-side comparison. Ignored by Rollback.

                  

                

                

                  

                    
                    
                    
Comma-separated domains for the new policy entry — leave blank to fall back to the package's own registered domains. Ignored by Rollback.

                  

                  

                    
                    
                    
Comma-separated task types for the new policy entry — leave blank to fall back to the package's own registered task types. Ignored by Rollback.

                  

                

                

                  
                  
                  
Fraction of sessions to route here once activated in canary mode — e.g. 0.1 ≈ 10% of sessions. Ignored for other deployment modes and by Rollback.
